#+TITLE: Using with anneal
#+OPTIONS: toc:nil todo:nil num:nil author:nil ^:nil

[[https://github.com/HaoZeke/anneal][anneal]] builds simulated annealing and related samplers from five components: the objective (Obj), the cooling schedule (Cool), the neighbourhood (Neigh), the move (Move) and the acceptance rule (Accept).
eindir supplies the objective and several of the pieces the other components use.
This page says which eindir item goes where; the anneal documentation covers the drivers themselves.

* Objective

Every anneal driver takes an =eindir_core::Objective<f64>=.
Gradient-based drivers, such as the GLE Langevin driver and local polish, take a type that also implements =Gradient<f64>=; [[file:gradients.org][Gradients]] shows how to provide one.
From Python, wrap a function with =eindir._core.PyObjective=.

* Start points and pilot designs

- The Bayesian pilot draws its design from =halton_unit=.
- Local polish draws its starts from =shifted_low_discrepancy_points= and =boundary_anchored_low_discrepancy_points=.

Use the same functions to seed your own chains, so that a change of driver does not also change the starts.
[[file:../tutorials/low-discrepancy.org][Low-discrepancy points]] shows the calls.

* GLE moves

The GLE Langevin driver builds its thermostat from =optimal_sampling_drift= and =GleThermostat=.
One drift matrix serves every timestep and temperature, because the drift sets how fast the momenta decorrelate and the covariance alone sets the temperature.
[[file:../explanation/gle.org][The GLE thermostat]] explains why.

* Surrogates

The additive independence driver fits an =AdditiveSurrogate= and draws proposals from it with =sample=, then accepts or rejects them with the true objective.
Because the surrogate implements =Objective=, the same fitted object can also stand in for the objective where a cheap value is enough.
