eindir is a small set of pieces that optimisers and samplers share.
Each piece is a trait or a plain function, so a driver can combine them without depending on any other driver.

* Objectives and bounds

=Objective<T>= is a function from a box in R^D to a number: =dim=, =bounds= and =eval=, with =eval_batch= and =global_min= as provided methods.
=Bounds<T>= is the box, with a slack that =contains= allows outside it, =clip= and a random =mkpoint=.
Everything else either consumes an objective (drivers, point sets that feed them) or produces one (surrogates, reduced objectives, wrappers of Python and C functions).

The trait cannot fail and has no gradient.
Gradients come from a separate trait, =Gradient<T>=, so that an objective without one is still a complete objective, and =DifferentiableObjective<T>= joins the two with a fused =value_and_gradient=.
Failure comes from a separate family, =TryObjective= and its relatives, so that an infallible objective pays nothing for it; see [[file:fallible-objectives.org][Fallible objectives]].

=eval_batch_parallel= evaluates rows with rayon from =EVAL_BATCH_PARALLEL_MIN= rows up.
It needs =Sync= objectives, which every =Objective= is, and keeps the row order.

* Point sets

Halton designs are deterministic and well spread; they seed starts, pilots and surrogate fits.
See [[file:low-discrepancy.org][Low-discrepancy point sets]].

* The GLE thermostat

A momentum thermostat with coloured noise that samples a band of frequencies evenly, for gradient-based samplers.
See [[file:gle.org][The GLE thermostat]].

* Surrogates

Cheap models fitted on a pilot design that implement =Objective= themselves.
See [[file:surrogates.org][Surrogates]].

* Bindings

The Python extension wraps a Python function as =PyObjective= and exposes the point sets.
The C ABI wraps a C function as =eindir_objective_t=, which Rust code sees as an =Objective= through =EindirObjectiveWrapper=.
See [[file:c-abi.org][The C ABI]] and [[file:../reference/api-primitives.org][Python API]].
